## Problem and intended users

For frequently admitted inpatients (an admission preceded by another admission within 365 days),
we predict the risk of an **unplanned transfer from a hospital ward to the ICU within the next 24 and
48 hours**. A risk score is produced once a day (08:00) for every patient on a ward, and the 10% of
patients with the highest risk form a clinical watchlist.

- Primary users: hospital operations managers and bed coordinators, for proactive ICU bed planning.
- Secondary users: ward clinicians, for closer monitoring of patients at risk of deterioration.

## Data

- Source: [MIMIC-IV v3.1](https://physionet.org/content/mimiciv/3.1/) (Johnson et al., 2024), `hosp` and `icu` modules.
- License: PhysioNet Credentialed Health Data License 1.5.0. Access requires a credentialed PhysioNet
  account, CITI "Data or Specimens Only Research" training, and signing the data use agreement.
  **The data is not included in this repository and must never be committed.**
- Version: v3.1 (released October 2024), downloaded October 2026; file integrity checked against
  PhysioNet's `SHA256SUMS.txt`.

After obtaining access, place these files (unchanged) under `data/raw/`:

The ICU charting tables (`chartevents`, `inputevents`, ...) are deliberately not used: they are recorded
only after ICU admission, i.e. after the outcome.

## Installation

Python 3.12.3 (tested with Anaconda). From the repository root:

```bash
pip install -r requirements.txt
```

This installs the pinned dependencies and the `icu_forecast` package in editable mode.

## Reproducing the results

Run from the repository root, in order. All settings (paths, seed, split proportions, cohort rules,
lab item IDs, drug classes) live in `config.yaml`.

```bash
python -m icu_forecast.clean      # ~7 min: clean raw tables, build cohort -> data/processed/*.parquet
python -m icu_forecast.split      # patient-level 60/20/20 split -> data/processed/split.csv
python -m icu_forecast.features   # ~3 min: daily ward snapshots, labels, features -> features.parquet
python -m icu_forecast.prepare    # train-only preprocessing -> artifacts/preprocessor.joblib
python -m icu_forecast.export_csv # optional: CSV copies of data/processed for SQL tools -> data/processed_csv

jupyter nbconvert --to notebook --execute --inplace notebooks/01_eda.ipynb notebooks/02_pca.ipynb
```

Outputs used in the report:

| Output | Content |
|---|---|
| `data/processed/cleaning_report.json` | Row counts for every cleaning step and cohort filter |
| `data/processed/features_report.json` | Snapshot counts and label rates |
| `data/processed/missingness_train.csv` | Missing share of every feature in the training split |
| `reports/figures/` | Figures 1 to 8 |

## Repository structure

```
config.yaml                 all settings
data/                       not committed: raw/ (read-only MIMIC-IV files), processed/ (rebuilt by the code)
notebooks/                  01_eda.ipynb (exploration), 02_pca.ipynb (dimension reduction)
reports/figures/            figures generated by the notebooks
src/icu_forecast/
    config.py               loads config.yaml, resolves paths
    clean.py                errors, duplicates, implausible values, cohort definition
    split.py                patient-level stratified train/validation/test split, fixed seed
    features.py             daily snapshots, 24 h / 48 h labels, leakage-safe features
    prepare.py              imputation, scaling, encoding fitted on training data only
artifacts/                  not committed: fitted preprocessors
```

## Leakage safeguards

- Patient-level split: all admissions of a patient are in one split.
- Labs are used only after their result is released (`storetime` before the snapshot time).
- Diagnoses come only from earlier admissions (they are coded at discharge).
- Snapshots stop at the first ICU entry, discharge, or death.
- Every imputation, scaling, encoding and PCA step is fitted on the training split only; the test split
  is not used until final evaluation.
